# Конструктор драйверов (бета)

**Больше не обязательно обращаться к разработчику за отдельным драйвером для каждой Java-сборки.** Администратор может самостоятельно настроить совместимость KaevCMS со своей игровой базой — **через панель управления, без написания PHP-кода**.

Конструктор связывает данные, нужные сайту, с таблицами и полями **LoginServer** и **GameServer**. Например: «логин игрового аккаунта → таблица `accounts` → столбец `login`». Настройки можно **скачать в JSON и передать другим администраторам**.

::: warning Бета-версия
Это **бета-функция**. Конструктор позволяет адаптировать многие **Java-сборки с MySQL/MariaDB**, даже если для них нет готового драйвера. Но это **не гарантия поддержки абсолютно всех сборок**: важны схема БД, алгоритм игровых паролей и необходимые функции. **MS SQL/PTS пока не поддерживается.**

Конструктор присутствует в актуальном исходном коде ветки 0.54.x. Проверьте, что он входит в установленную вами сборку; отсутствие официального ZIP с этой функцией не следует путать с её наличием в исходниках.
:::

## Что умеет конструктор

| Тип профиля | Назначение |
| --- | --- |
| **Логин-сервер** (LoginServer) | Поиск игровых аккаунтов, регистрация, смена паролей, статус аккаунта — если эти операции поддерживает игровая база. |
| **Игровой сервер** (GameServer) | Персонажи, уровни, PvP/PK, игровое время, герои, замки, рейтинги и фильтры — по доступным таблицам. |

Ненужные функции можно отключать. Уже готовые драйверы **L2J Mobius** и **RUSaCis** остаются доступными, и их можно использовать как шаблоны.

## Как создать собственный драйвер

1. Откройте **Админка → Серверы → Драйверы**.
2. Выберите **«Логин-сервер»** или **«Игровой сервер»** и нажмите **«Создать драйвер»**.
3. Если ваша сборка похожа на Mobius или RUSaCis, **возьмите готовый профиль за основу**, чтобы не заполнять всё с нуля.
4. Укажите название драйвера, кодировку и нужные функции.
5. Сопоставьте поля сайта с **реальными таблицами и столбцами** вашей игровой БД. Для LoginServer при необходимости задайте поддерживаемый алгоритм игрового пароля.
6. Для GameServer настройте персонажей, связи с другими таблицами, статистику и фильтры.
7. Нажмите **«Сохранить драйвер»**.

Названия таблиц можно посмотреть через **phpMyAdmin** или другую панель управления MySQL. Указывайте **имена таблиц и колонок**, а не данные конкретных игроков.

## Как подключить драйвер к серверу

**Сохранение профиля ещё не переключает действующий сервер.**

1. В разделе **«Серверы»** откройте настройки **LoginServer** или **GameServer**.
2. Выберите свой драйвер и сохраните параметры подключения к игровой БД.
3. Выполните **«Проверить подключение»**.
4. На карточке сервера нажмите **«Применить JSON и проверить»**. KaevCMS проверит нужные таблицы и поля и только после успешной проверки применит профиль.
5. Проверьте на тестовом аккаунте регистрацию, вход, персонажей и нужную статистику.

Проверка структуры **не изменяет игровую БД**, но **не подтверждает автоматически**, что клиент игры примет созданный пароль или что все возможности сборки корректно работают. После изменений профиля или реквизитов БД требуется повторное применение.

## Как экспортировать и импортировать JSON

**Экспорт:** откройте **Серверы → Драйверы**, нажмите **«⋯»** у нужного профиля → **«Экспортировать»**. Скачается `.json`-файл, которым можно поделиться.

**Импорт:** нажмите **«Импортировать»**, выберите `.json` (**до 256 КБ**) и подтвердите. CMS проверит формат и добавит профиль. При совпадении ID создаст копию со свободным идентификатором. После импорта нужно **проверить настройки и отдельно применить драйвер к подключению**.

У LoginServer и GameServer **отдельные профили**: если вы настроили оба, экспортируйте оба файла.

::: tip Безопасность
JSON содержит **названия таблиц, полей и функции драйвера**, но **не содержит адресов БД, логинов и паролей подключения**. Произвольный SQL и PHP внутри JSON запрещены. Чужой профиль всё равно проверяйте перед использованием.
:::

## Ограничения

- Только **MySQL/MariaDB**, не MS SQL/PTS.
- Поддерживаемые алгоритмы игрового пароля: **SHA-1/Base64, BCrypt `$2a$`, SHA-1/MD5/SHA-256/Whirlpool (hex)**. Произвольные алгоритмы не допускаются.
- Для создания аккаунтов нужны подходящие поля и **уникальный индекс по логину**.
- Не все нестандартные схемы рейтингов и игровые операции доступны через JSON-профиль.
- Для [передачи предметов в игру](/guide/reward-delivery) по-прежнему нужны очередь наград и обработчик на стороне GameServer.

**Главная идея:** вместо ожидания нового PHP-драйвера администраторы теперь могут **самостоятельно создавать, проверять и обмениваться профилями** для своих Java-серверов.
