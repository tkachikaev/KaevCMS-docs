# Режимы отправки почты

Настройка находится в **Админка → Настройки → Почта → Доставка**. Все три режима используют один и тот же настроенный **SMTP**. Отличается только то, **когда и где KaevCMS выполняет отправку**.

## Сравнение трёх режимов

| Параметр | Синхронный | Асинхронный | Асинхронный с очередью БД |
| --- | --- | --- | --- |
| **Когда отправляется письмо** | Во время запроса игрока | В отдельном процессе после ответа сайта | Когда задание возьмёт worker или планировщик |
| **Скорость ответа сайта** | Ниже: ждёт SMTP | Высокая | Высокая |
| **Скорость запуска отправки** | Сразу, но блокирует запрос | Обычно сразу после ответа | Worker — обычно быстро; cron — после ближайшего запуска (возможна задержка в минуты) |
| **Нагрузка на сайт** | SMTP занимает PHP-процесс веб-запроса | Дополнительный кратковременный PHP-процесс | Небольшая на веб-запрос; дополнительная работа очереди и БД |
| **Если SMTP недоступен** | Ошибка; автоматической повторной попытки нет | Отдельный процесс может завершиться с ошибкой; повторов нет | Есть повторные попытки, затем запись в **неудавшихся заданиях** |
| **Если сайт/процесс перезапустился** | Незавершённая отправка может прерваться | Незавершённая отправка может потеряться | Ожидающие задания сохраняются в БД, пока она доступна и данные не удалены |
| **Дополнительные требования** | Только рабочий SMTP | Сервер должен уметь запускать фоновый процесс | Таблицы очереди в CMS и **cron Scheduler или постоянный worker** |
| **Где удобнее использовать** | Простая установка, мало писем | Небольшие нагрузки, если фоновые процессы разрешены | Рабочий сайт и массовые регистрации |

**Ни один режим не гарантирует доставку в почтовый ящик:** провайдер может отклонить сообщение позже или поместить его в спам. Разница в таблице касается обработки **заданий на отправку самой CMS**.

## Как включить каждый режим

### 1. Синхронный

1. Настройте SMTP и успешно отправьте [тестовое письмо](/guide/mail).
2. Во вкладке **«Доставка»** выберите **«Синхронный»**.
3. Сохраните. **Worker и cron для почты не требуются.**

Это самый простой и начальный режим. Но если SMTP отвечает медленно, игрок будет ждать окончания попытки отправки.

### 2. Асинхронный

1. Сначала настройте SMTP.
2. Во вкладке **«Доставка»** выберите **«Асинхронный»** и сохраните.
3. Дождитесь автоматической проверки сервера. При успехе режим включится; при неудаче останется прежний.
4. Проверьте получение настоящего письма игроком.

**Постоянный worker не нужен.** Сервер должен разрешать запуск дочернего процесса PHP. Некоторые виртуальные хостинги это запрещают. Задание не записывается в очередь БД: при аварии процесса повторить его автоматически будет нечем.

### 3. Асинхронный с очередью в БД

1. Настройте SMTP.
2. Убедитесь, что на сервере **работает планировщик Laravel каждую минуту** или **постоянный queue worker**.
3. Во вкладке **«Доставка»** выберите **«Асинхронный с очередью в БД»**.
4. Дождитесь успешной проверки; затем сделайте тестовую регистрацию или запрос письма.

**На VDS:** настройте worker по [инструкции для Ubuntu](/guide/vds). Он обрабатывает задания без ожидания следующей минуты cron. Сам планировщик нужен CMS и для других фоновых задач.

**На виртуальном хостинге:** постоянный worker может быть недоступен. Тогда запустите **Laravel Scheduler через cron каждую минуту**, если это поддерживает ваш тариф. Планировщик вызывает встроенную обработку очереди (`kaevcms:queue-drain`). Если нет ни cron, ни worker, **режим очереди использовать нельзя**: письма останутся ждать.

::: info Скорость очереди
Стандартный запуск `kaevcms:queue-drain` ограничен **100 заданиями за один проход** (общий лимит для всех очередей). Фактическое количество отправленных писем зависит от скорости SMTP и наличия других заданий. С постоянным worker обработка может идти быстрее.
:::

## Повторы, потеря писем и диагностика

При временном сбое SMTP задания **очереди БД** повторяются с паузами. Если попытки исчерпаны, письмо **не исчезает бесследно**, а попадает в список **неудавшихся заданий** в разделе **Система → Очереди**. После устранения причины отправку можно повторить вручную. Автоматическая очистка служебных данных со временем может удалить старые неудавшиеся задания, поэтому не оставляйте их без внимания.

Если планировщик остановился, задания остаются в базе, но **не отправляются до возобновления обработки**. Если SMTP принял письмо, однако оно не дошло адресату, повтор из очереди не всегда поможет — проверяйте и почтовый сервис.

**Рекомендация:** для сайта с регулярными регистрациями выбирайте **очередь БД**, если есть работающий cron или worker. При отсутствии такой возможности используйте **синхронный режим**; фоновый режим — компромисс по удобству, но не по надёжности.
