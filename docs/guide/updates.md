# Обновление KaevCMS

Способ обновления зависит от среды и типа установочного пакета. **Не используйте ZIP обновления вместо полного архива установки**.

## Перед обновлением

1. Запишите точную установленную версию (например, из системной информации).
2. Откройте [релизы KaevCMS](https://github.com/tkachikaev/KaevCMS/releases).
3. Проверьте диапазон поддерживаемых исходных версий **в манифесте пакета**.
4. Сделайте резервную копию файлов, базы CMS, .env, public/uploads и других пользовательских данных.
5. По возможности проверьте обновление на отдельной копии проекта.
6. Сверьте SHA-256 архива с опубликованной контрольной суммой.

## VDS

У KaevCMS предусмотрены CLI-обновление и локальный VDS Update Agent. Конкретный порядок зависит от способа установки и релиза. Не запускайте старые скрипты обновления от имени веб-пользователя и не меняйте права на исходный код ради удобства.

Руководствуйтесь инструкцией своей версии: [официальные VDS updates](https://github.com/tkachikaev/KaevCMS/blob/main/docs/ru/UPDATES.md).

## Виртуальный хостинг

Для совместимых версий используется кумулятивный Web Updater в административной панели. Поддержка прямого перехода определяется **содержимым конкретного Update ZIP**, а не просто его названием.

## После обновления

- Проверьте версию CMS, состояние миграций и системную диагностику.
- Проверьте публичный сайт, вход в кабинет и доступность игровых баз.
- Убедитесь, что пользовательские данные и настройки сохранились.
- Посмотрите журнал обновления; сохраните бэкап до окончания проверки.

::: danger
Нельзя публиковать .env, пароли, APP_KEY или резервные копии в GitHub Issues и публичных чатах.
:::
